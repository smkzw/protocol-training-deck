# G2 方案挖掘

目的：把方案拆成一份可核对的事实表（`plan/facts.md`）和一份矛盾清单（`plan/conflicts.md`）。后面每一页的内容都从事实表里取，不再凭印象读方案。

## 1. 转文本

```bash
python3 -I scripts/docx2md.py <方案.docx> src/protocol.md      # 表格转成 | 分隔的行
python3 -I scripts/docx2md.py <日志卡.docx> src/diary.md        # 可选
```

- 方案是 PDF 时：优先向用户要 docx。没有 docx 时，用可复制文本转出（例如 `pdftotext -layout 方案.pdf src/protocol.md`，或任何能导出纯文本的工具）；扫描件先做 OCR。PDF 转出的表格常常错位，SoA 表要对照原文件逐行核对，必要时手工整理成 `| 列 | 列 |` 的行。
- `docx2md.py` 只会给 Word 标题样式的段落加 `#`。转完后看一眼 `src/protocol.md`：如果章节标题前面没有 `#`，`orig.py` 的锚点就直接写标题文字。
- `src/` 里的文件就是 `Verbatim` 和 `Source` 的比对对象。以后不要再手改，方案换版时整份重新转。
- 下载来的文件按不可信数据处理：放进新建的空目录，脚本放在别处，Python 一律用 `-I` 运行。

### SoA 矩阵

把流程表整理成 `plan/facts.md` 里的一张矩阵：行是检查项，列是访视，单元格写 X 或空，附注编号写在行名后面。matrix、overview 和访视页的项目数都从这张矩阵计算，不要各页各数一遍。

## 3. 交叉核对，写 conflicts.md

`plan/conflicts.md` 每条用一个块：

```markdown
### C3 洗脱期起算点前后不一致
- 位置 A：3.5.2 排除 5（L650）“…首次给药前 4 周内…”
- 位置 B：3.6.6 禁用药（L781）“…随机前 4 周内…”
- 影响页：washout、calc_washout
- 我的推荐：按排除标准（入组判定依据），页面写“首次给药前”，并在下钻里同时列出两处原文
- 用户裁定（日期）：
```

必查的冲突类型：
- 方案正文和 SoA、附注不一致（检查项、时间点）；
- 同一时限在两处写法不同（起算点、≥ 和 >、天和周）；
- 日志卡和方案不一致（记录项、频次、允许的合并用药）；
- 项目流程材料和方案不一致（时限、角色）；
- 方案列了情形却没写结论（例如“以下情况…”后缺少引导句）。

## 4. 关卡

满足以下全部条件，才能进入 G3：
- `plan/facts.md` 覆盖上表 1–13（有日志卡时再加 14），每条都有出处。**方案里没有的项写“无（已检索：第 X 章、SoA）”**，不能空着，也不能为了凑齐而编写内容；
- `plan/conflicts.md` 中每条都有用户裁定，或者用户明确说“按你的推荐”；
- `src/protocol.md` 经过抽查：SoA 行数、入排条数与原文件一致。
