# G1 需求确认

目的：在读方案之前，先把会改变整套稿子的几件事问清楚，写进 `plan/TASK.md` 的“口径”一节。只问会改变产出的问题，用户已经说过的不再问。

## 必问 6 个问题

一次发出，可以用提问工具；没有提问工具就列成编号清单，等用户答复。

1. **材料清单。** 方案是哪个版本、文件在哪里？有没有日志卡、入组审核表、项目流程截图（如潜在受试者识别流程、入组审核流程、文件命名归档规则）、实验室手册、ICF？
   用途：确定事实来源，以及哪些页可以写“项目流程（CRO）”。
2. **听众与场合。** 听众是谁（CRC、CRA、研究者、项目组、招募人员）？在什么场合讲（启动会 SIV、项目组内训、中心培训）？谁来讲？
   用途：决定逐字稿的口吻和背景章节的深浅。听众写在暗线里，不写在封面上。
3. **范围与篇幅。** 覆盖全流程，还是只讲某几个阶段？预计讲多久？
   用途：每页约 3–5 分钟。完整的全流程稿通常有 30–45 页，需要 2–3 小时，可以分场讲。只有 1 小时时，按 `workflow/02-outline.md` §2 合并到约 15–20 页，或者只讲指定的章节。
4. **方案外内容的处理。** 方案没写、但实践中常见的做法（检查顺序、资料整理、时限参考值），是不写，还是写并标 `[建议]`？
   默认：只在有医学理由时写，并标 `[建议]`。
5. **背景章节。** 要不要讲疾病和药物机制？有没有可公开的药物资料（IB 摘要、已发表文献）？能不能用外部生图？
   默认：讲；用内置 SVG 示意图；药物特点只写方案或公开资料能支持的内容。
6. **品牌与署名。** 页脚写什么（部门｜年月）？封面标题怎么写？是否沿用内置的康哲品牌？
   用途：其他公司使用时，要替换 `engine/static/assets/logo_bot.svg` 和 hero 图，见 README。

## 默认口径（用户没有特别说明时）

把下面这张表原样写进 `plan/TASK.md`，用户改了哪条就改哪条。

| 项 | 默认 |
|---|---|
| 结构 | 封面、目录、章节页；第一章讲背景与设计，之后按受试者流程推进，最后一章讲特殊情况 |
| 视角 | 医学人员讲方案要求；运营操作只讲方案规定，不教做事 |
| 方案外做法 | 有医学理由才写，标 `[建议]` 或 `[操作建议]` |
| CRO/项目流程 | 只有在用户提供材料时才写，标“项目流程（CRO）”，不擅自加时限 |
| 示例 | 全部使用虚构受试者编号（如 S01003）和虚构日期，日期从一个虚构的 D1 推算 |
| 文件命名与资料 | 用户给了命名规则才演示；资料脱敏 |
| 逐字稿 | 每页每步都写，放进演讲者窗口 |
| 字号 | 最小 12px |
| 动画 | 不自动播放 |

## 什么时候必须停下来再问

- 方案两处说法矛盾（例如同一条洗脱期，前后起算点不同）；
- 判定口径会影响受试者安全或合规，例如 SAE 的住院例外、是否需要研究者评估；
- 用户材料（CRO 截图）与方案冲突；
- 用户要求的写法会变成“指挥运营”。

问的时候给出你的推荐和理由，例如“推荐按方案 6.2 写‘研究者评估是否属于 SAE’，因为方案列了这些情形但没写结论”，让用户确认或改选。答复写进 `plan/TASK.md` 的“用户裁定”一节，并注明日期。
