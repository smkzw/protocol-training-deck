# G7 QA

QA 分三条线：视觉、交互、内容。三条都要做，并记进 `plan/qa-log.md`。

## 1. 视觉

1. 运行自动 QA：`python3 -I scripts/qa.py`（默认存每页最终态截图；检查动画时加 `--shots 2`）。退出码 0 才进入下一步。
2. `summary` 为空（`{}`），所有问题清零。
3. 打开 `qa/shots/`，按 `reference/visual-qc.md` §2 的清单逐页看最终态。
4. 交付前跑一次多视口检查：`python3 -I scripts/qa.py --all-viewports --shots 0`，退出码为 0。
5. 关键页逐步看（`python3 -I scripts/qa.py --shots 2`）：所有有反例、关键帧、token 的页面，以及构建提示 `autofit skipped` 的页面。
6. 每修一轮，重新构建、重新跑 QA，再看一遍改过的页面。

## 2. 交互

按 `reference/visual-qc.md` §3 手动过一遍：不自动播放、逐步推进、末步翻页、倒退进入停在末步、S 演讲者窗口同步、目录跳转、下钻弹层、打印。进页闪现（ENTRY_FLASH）、下钻开关（DRILL）和演讲者窗口的消息约定（PRESENTER_SYNC）已由自动 QA 覆盖，手动时重点看演讲者窗口的画面和打印效果。

## 3. 内容（独立核对）

让一个没有参与制作的审阅者（另一个 Agent 或同事）只读 `src/protocol.md`、`content/` 和 `plan/facts.md`，逐页核对。给审阅者的要求：

```
你是临床试验方案审阅者。逐页对照 src/protocol.md 核对 content/pages/*.py、content/meta.py、content/notes.py 中的每个事实：
数字、日期、窗口、剂量、访视项目、入排阈值、报告对象与时限、量表分级。
另外专门检查：
1. 原文写“建议/尽量/最好/可/可不”的地方是否被写成了“须/应/不得”；
2. 方案外的说法是否标了 `[建议]`或来源；
3. 对比类说法（最多、最轻、仅此一次）是否与 SoA 一致；
4. 叠加规则（窗口 + 给药间隔、两种药物洗脱）是否算对；
5. 是否有指挥运营的措辞。
每条问题写：页面 pid、页面原文、方案原文与行号、问题、建议改法。分 ERROR（事实错）/ WARN（强度或标注不当）/ NOTE。
不要修改任何文件。
```

拿到报告后，逐条对照方案原文复核，确认无误再改。改完重跑构建、`check_project.py` 和视觉 QA。
