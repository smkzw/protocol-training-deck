# 逐字稿与演讲者模式

## 1. 数据结构（content/notes.py）

```python
HERO_NOTES = {            # 封面、目录、章节页（键为章节编号）
    'cover': '各位好。今天讲……依据方案 V1.0。',
    'toc':   '整体分四章：……',
    '01':    '第一章，研究背景与设计：……',
}
NOTES = {                 # 正文页：(开场, [第 1 步, 第 2 步, …])
    'incl_easi': ('疾病严重程度的入排要求。先看方案原文，再看两个例子。', [
        '入选 2 到 4：……',
        'S01003 在 V1……',
        '同一位受试者到基线……',
        '排除 1 看肝功能：……',
    ]),
}
```

- 开场对应第 0 步：刚翻到这页，只有标题和强调句。
- 第 k 段对应按下第 k 次之后的画面。段数必须等于页面步数，构建时会检查。
- 封面、目录和每个章节页都要有 HERO_NOTES。

## 2. 写法

| 项 | 规范 |
|---|---|
| 长度 | 开场 20–50 字；每步 60–150 字，约 20–40 秒 |
| 口吻 | 讲给人听的完整句子，可以用“这里”“看图中……”指向画面；不用禁用词（见 copy-rules），也不用套话“这一页讲”“这一页展示了”“可以看到”“值得关注的是”“接下来我们将”（康哲讲稿规范，`check_project.py` 会提示） |
| 内容 | 先读画面上新出现的内容，再给出方案依据或理由；数字读完整（“300 毫克”“正负 3 天”） |
| 出处 | 涉及规定时说出条款，例如“方案 6.2 规定……” |
| 反例 | 说清错在哪里、方案怎么规定、后果是什么（如“该样本不符合方案要求，按偏离记录”） |
| 建议 | 方案外内容明确说“这是建议做法，原因是……” |
| 来源 | 项目流程页的第一段说明“这一流程来自项目的……，不是方案条款” |
| 衔接 | 最后一步可以用一句话引出下一页，但不要每页都这样 |
| 不写 | 开场白客套、重复强调句原话、“大家记住”“很重要” |

### 示例（访视页，5 步）

下面是演讲者窗口里**显示出来**的样子。`【1】`…`【5】` 由构建自动加上，在 `notes.py` 里只写正文，不要自己写编号。

```
开场：V4 是第 2 次给药。
【1】V4 的目标日是 D29，窗口正负 3 天。按 D1 等于 12 月 1 日举例，就是 12 月 26 日到 1 月 1 日。
【2】本次采三管血：血常规、血生化和 PK。PK 只能在给药前 1 小时内采。
【3】反例：先给药，给药后 20 分钟才采 PK。时间点不符合方案，清单上这一项是红叉，样本按偏离记录。
【4】正确做法：08:50 采 PK，09:30 给药，间隔 40 分钟，在 1 小时以内。
【5】给药后留观至少 30 分钟。下次 V5 仍按 D1 推算窗口，不随这次的实际日期顺延。
```

## 3. 演讲者模式（运行时已内置，不需要改）

- 放映时按 **S** 打开演讲者窗口（新窗口，允许浏览器弹窗）。
- 窗口内容：当前页预览、下一页预览、逐字稿、计时器、页码与步数。
- **逐步同步**：主窗口每按一步，演讲者窗口就高亮对应的段落（`.now`），并自动滚到该段；在演讲者窗口按 ← → 也能控制主窗口。
- 预览帧显示该页最终状态（`?preview`），不播放动画。
- 章节页、封面、目录显示 HERO_NOTES。
- 逐字稿在主窗口里不可见（`<aside class="notes">`），打印时也不输出。

## 4. 检查

- `python3 -I engine/build.py` 不报 `script has N step paragraphs` 的 WARN。
- 在浏览器中按 S，翻 3 页、每页按几步，确认高亮段落跟着走（`workflow/06-qa.md` 有自动检查方法）。
- 抽读 5 页逐字稿，要能不看画面听懂。
