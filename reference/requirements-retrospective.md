# 需求复盘：从一个项目的 5 轮反馈到通用规则

本文件将培训制作需求整理为通用规则，并标明其在技能中的实现位置。

> 示例使用虚构研究 DEMO-301。

## 第 0 轮：原始需求

## 设计取舍（为什么这样做）

1. **固定页目录 + 可变页规则，而不是一个大模板。** 固定页让弱模型知道“每页取什么、怎么摆”；可变页规则防止把某个研究的结构硬套到别的研究上。
2. **由代码生成页面，而不是手写 HTML。** 坐标、步骤和关键帧都由 Python 生成，构建器统一检查结构、逐字稿、标题长度和原文一致性，弱模型也难以写出结构性错误。
3. **项目自带引擎。** `new_project.py` 把 `engine/` 拷进项目，这样项目在任何机器上都能构建，技能以后升级也不会影响已经交付的稿子。
4. **原文校验写进构建。** `Verbatim` 和 `Source` 让“页面上的方案原文与方案不一致”变成构建错误，而不是靠人眼发现。
5. **自动 QA 与人工截图并存。** 自动检查覆盖溢出、重叠、闪现、逐字稿；疏密、复原、语义只能靠看截图，所以写成了清单。
6. **示例用虚构研究。** 既避免泄露项目资料，也避免 Agent 照抄某个真实研究的内容。
