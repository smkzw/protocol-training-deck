# 页面模式手册（P1–P20）

每种模式按同样的结构写：用途、构图（可用区 1168 × 524（总画布 1168 × 564，顶部 40 是强调句），坐标 y 为 0..524）、scene 节奏、组件与代码要点、正反例怎么放、变体、避免什么。坐标是起点，不是模板。内容长短不同时，要按内容调整，并用截图确认。

通用约定：
- `R` 表示右栏起点，常取 400、560、580 或 600。
- 旁白槽位见 `workflow/03-page-design.md`。
- 示例代码里的 `p` 是 `Page`，组件说明见 `kit-api.md`。
- 每种模式下面都标了可以对照学习的示例页：**demo** 表示 `examples/demo-study` 中有对应页。

---

## P1 分栏递进（背景、机制、因果链）
- **用途**：疾病背景、病理链、现有治疗阶梯，适合“A 导致 B，B 导致 C”的内容。
- **构图**：3–4 栏，每栏宽 260–280，栏间放箭头 `p.wire`；每栏是图标 + 标题 + 2–3 行要点；示意图放在第一栏上方或左侧 (0,0,360,380)。
- **scene**：一栏一步，箭头随下一栏一起画出（`wire(..., s=k)`）；最后一步给出“未满足需求”或“本药物的位置”，用品牌橙描边 `nd on`。
- **正反例**：背景页可以不放反例，改为放一个“容易混淆”的标签（琥珀色 tag），例如“仅凭症状不能诊断”。
- **避免**：栏内大段文字；四栏宽度不一致。
- **代码要点**：栏内容少时用大图标 + 居中排版（`display:flex;flex-direction:column;justify-content:center`），不要让 2 行字顶在高卡片的上沿；循环关系用一条从末栏下沿绕回首栏的虚线 `wire`（`brand dash`）。
- **demo**：bg_disease。

## P2 研究信息 / PICOS
- **用途**：研究基本信息、PICOS。
- **构图**：顶部题目条 (0,0,1168,56)，`pn tint`，f16 粗体；编号条 3–4 个 tag；事实网格 2×4 的小卡（每卡 270×70，标签 f12 mut、值 f16 b）；分组条按比例画 (x, y, w·比例, 28)，两组颜色分别为品牌橙和灰。PICOS 版是五行，每行左侧放 56×56 的字母方块（P/I/C/O/S），右侧写内容。
- **scene**：题目 → 设计与例数 → 分组展开（`fx='wipe'`）→ 主要终点。
- **代码要点**：分组条宽度用计算得出，例如 `w * 160/240`，不要估算。
- **demo**：study_info。

## P3 量表卡网格
- **用途**：研究评估量表、多个评分工具。
- **构图**：2×2 卡（每卡约 570×190），卡内依次是名称（f16 b）、评估者 tag、条目列表（f13，两列）、分级刻度条（一条横带，分段着色并标分值）。
- **scene**：第 k 步高亮第 k 张卡：该卡写 `k={k: {'c': 'on'}, k+1: {'c': ''}}`，其余卡在这一步写 `{'c': 'is-dim'}`，同时展开该卡的刻度条（`fx='wipe'`）。
- **必须写**：条目内容、每条分值、总分范围、分级定义。只写名称不合格。
- **代码要点**：卡内自己排版（标题行 + 条目 + 刻度条）时，`p.panel` 不传 title，必须加 `style='display:block'`，否则内容垂直居中会压到刻度条。
- **避免**：四张卡同时铺满文字、没有焦点。
- **demo**：scales。

## P4 分层时间线
- **用途**：研究设计总览、终点挂靠到访视、长周期研究。
- **构图**：轴 y≈150，x 从 40 到 1128；上层分期色带（y 60–90，半透明）；中层访视点，关键访视用 r=12 的大点，其余 r=7，下方写 V 编号和周；下层给药和采样标记（y 200–300，用 `tag`）；右下或底部放 KPI 小卡。短期（筛选、导入）用 `piecewise_axis` 拉宽。
- **scene**：分期 → 访视 → 给药 → 采样/评估 + 窗口规则。每步一层。
- **demo**：overview。

## P5 访视矩阵 + 聚焦问题
- **用途**：访视项目总览、合并访视页的差异小矩阵。
- **构图**：行是检查项（按类别分组，组名放左侧竖排），列是访视。单元格 `cel` 小方块 (cw≈52, ch≈22)，有项目的格子加 `on`。右侧 (880–1168) 放“聚焦问题”卡，每步换一个问题。
- **scene**：整体淡显 → 每步点亮一行或一列（`k={k: {'c': 'on'}}`），聚焦卡同步更换（`s=k, o=k+1`）。
- **代码要点**：矩阵数据从 `plan/facts.md` 的 SoA 抄进页面模块的一个 dict，访视页的项目数也从这个 dict 计算。格子尺寸按访视数和项目数算：`CW = min(84, (860 - 左侧行名宽) / 访视数)`，`CH = min(66, 可用高 / 项目数)`；访视超过 12 次时按阶段拆成两页或只列代表访视。
- **demo**：matrix（8 次访视 × 4 类项目）。
- **避免**：高亮条与内容不对应；全部单元格同一个颜色。

## P6 规则原文 + 图形测量 + 判定板
- **用途**：带阈值的入排条款（评分、化验、体重指数、年龄）。
- **构图**：左栏原文卡 (0,0,540,176)，用 `quote_card` + `Verbatim`，阈值加 `__下划线__`；左下判定板 (0,196,540,…)，用 `verdict_board`；右栏阈值条，每条 64 高，用 `threshold_bar`；右下提示卡 `alert`。
- **scene**：原文 → 例 1 达标（判定板 ✓）→ 同一人在另一时点不达标（✗，红卡）→ 另一条款（如化验），给出复查规定（琥珀）。
- **demo**：incl_easi。

## P7 原文 / 解析两栏
- **用途**：文字类条款（病史、既往治疗、洗脱期、合并用药的总体要求），即“方案怎么写、我们怎么理解”。
- **构图**：左栏原文 (0,0,540,~380)，`quote_card`，可以分 2–3 张；右栏解析 (580,0,588,~380)：每条原文对应一行解析（图标 + 一句话 + 数值 tag），用细线 `p.wire` 连接原文行和解析行。
- **scene**：原文出现 → 逐条解析（每步 1–2 条）→ 容易误读的一条（琥珀色，写清两种读法和方案原意；拿不准的写进 conflicts 问用户）。
- **避免**：解析改写了原文的意思，例如把“建议”写成“须”、把“可不”写成“不得”。
- **代码要点**：左右两栏用同一组 `(y, h)`，连线画在两栏中线之间；“容易误读”的提示卡用 `alert(..., 'warn')` 盖在被误读那一行的解析上（同坐标）。
- **demo**：excl_prior。

## P8 时点倒计时轴
- **用途**：洗脱期倒推、补救治疗时机、超窗后可约日期。
- **构图**：横轴 (40–1128, y≈120)，右端是起算点（首剂、随机），用 `stamp` 或大 tag；向左画倒推区间 `band`；下方 2–3 行案例，每行一条药物或事件的横条。
- **scene**：起算点 → 规定区间 → 正例横条落在区间外 ✓ → 反例差几天 ✗ → 复杂情形（两种药物取较晚者，或叠加间隔下限）。
- **代码要点**：坐标用 `day_axis(L, R, d0, d1)` 换算，日期用 `StudyDates`；跨月倒推时直接用 `datetime.date` 相减（`X = lambda d: X0((d - D1).days)`）。每行一条横条：末次用药点 → 末次 + 洗脱期，横条终点不晚于 D1 竖线即符合；D1 推后用竖线的 keyframe `x` 表示。
- **demo**：washout_calc。

## P9 日历网格
- **用途**：筛选期时限、日志卡天数、复查落点、窗口落到真实日期。
- **构图**：`Calendar(p, 起始周一, x=0, y=30, cw=78, ch=56, weeks=5)`，占 546×310；右栏 (600–1168) 放规定卡 `kv_card` 和计数环 `gauge`。
- **scene**：起算日 → 区间带 `band` → 记录日标记 `mark` → 不足的情形（空白日用 `ring` 圈出，`gauge` 改为红色）→ 越界的复查。
- **demo**：screen_cal。

## P10 计算器
- **用途**：洗脱期计算、剂量按体重换算、给药间隔、依从性百分比。
- **构图**：左侧“输入”卡（2–3 个输入框样式的值），中间是算式行（f20 num，运算符用 f28 mut），右侧是结果卡（用 `stamp` 显示 ✓/✗）。数值变化用 `count={k: [from, to, 小数位]}` 滚动。
- **scene**：输入 → 代入算式 → 结果 ✓ → 换一组输入得到 ✗ → 边界值（恰好等于阈值时，按方案写的 ≥ 还是 > 判定）。算法本身容易错时（例如分母用错），在“换一组输入”之前加一步算法反例。
- **代码要点**：同一个数值元素可以同时带 `count`（数字滚动）和 `k`（改颜色 `c`）；输入格用 `k={步: {'t': 新值}}` 换数。结果印章和结果文字每步一组，`s=k, o=k+1`。
- **demo**：nrs_calc。

## P11 访视清单 + 图形演示
- **用途**：每次访视页（模板访视、差异访视）。
- **构图**：左栏 `visit_checklist(p, 标题, 小字, groups)` (0,0,380,524)；右栏 (R=400) 上方是窗口条（日期格子 + 绿色窗口带），中间是本次样本（`tube_html`）或评估示意，中右放反例/正例卡位，底部是计时环、下次访视卡和旁白。
- **scene**：窗口 → 本次项目（清单对应项打勾）→ 陷阱（清单该项 `fail`，红卡，`ring` 圈住出错处）→ 正确做法（同一项改为 `done`，绿卡替换红卡）→ 给药、留观、下次窗口。
- **代码要点**：清单的 frames 写成 `{3: 'fail', 4: 'done'}`；红卡 `s=3, o=4`，绿卡 `s=4`，两张卡同坐标。
- **demo**：v4。

## P12 当日时间轴
- **用途**：给药日安排、PK 窗口、给药后留观、ECG 时点。
- **构图**：`time_axis(p, 150, 1150, 0, 8, 12)`；左侧 4 条泳道标签（到达、评估、采血、给药）；给药时刻竖线（品牌橙，宽 3）；PK 窗口是虚线框（绿色半透明）；下方左侧放要点清单，右侧放提示卡和旁白。
- **scene**：给药时刻 → 正常的一天（各条 `bar` 依次从左滑入）→ 反例一（给药推迟：竖线和窗口用 keyframe 右移，PK 条变 `err`）→ 反例二（留观不足：留观条变短、变 `err`）→ **回到正常**（最后一步用 keyframe 把位置、宽度、class 全部改回去）。
- **demo**：dose_day。

## P13 决策流 + 案例 token
- **用途**：AE/SAE 判定、复查与重新筛选、退出、补救、揭盲条件。
- **构图**：上半部 `Flow(p)`：起点 node → 菱形 diamond → 2–3 个结果 node，占 (0–940, 0–180)；左下放规定或原文卡，右下放案例卡位 (580,200,588,190)；底部放报告表或旁白。
- **scene**：流程骨架（第 1 步全部画出）→ 例 A 沿路径走（`token({2:'a'})`，案例卡 A）→ 例 B 走另一分支（卡 B 替换卡 A）→ 反例 C（停在错误的地方，红卡）。
- **代码要点**：`f.route('a', 'ae', 'q1', 'sae')`；平行路径用 `('ae', 0, 10)` 加偏移，避免 token 重叠。
- **demo**：ae_flow。

## P14 泳道 + 信封 token
- **用途**：潜在受试者识别、审核流程、揭盲操作，适合多个角色接力的流程。
- **构图**：`Lanes(p, ['crc','pi','cra','mm'], x=0, y=0, w=860, lane_h=70)`；节点 `lanes.box(...)`；右栏 (880–1168) 放邮件或系统界面 `screen_mock` 和提示卡；旁白通栏放底部。
- **scene**：泳道和正常路径的节点 → 信封 token 走正常路径，邮件界面出现 → 退回路径（琥珀 token，退回卡）→ 不支持或另一种结果。
- **来源标注**：流程来自 CRO 材料时，小字写“项目流程（CRO）”，旁白第一句说明来源。
- **demo**：review_lanes。

## P15 资料包 / 归档 / 命名 / 脱敏
- **用途**：筛选或基线审核资料、文件命名、脱敏要求。
- **构图**：左侧散落的文档 `doc_mock`（4–6 张，每张 150×110，略有错位）；中间是分类文件夹（`folder` 图标卡）；右侧是 PDF 文件名列表（f13 num，如 `S01008-筛选期-筛选期病历.pdf`）；脱敏用 `redact` 黑条覆盖姓名。
- **scene**：散乱资料 → 归入各类别（keyframe 移动文档到文件夹，`k={2: {'x':…, 'y':…}}`）→ 命名 → 脱敏（黑条 wipe）→ 反例：命名错或缺一类，`ring` 圈出。
- **避免**：写成“CRC 应该…”。只呈现材料规定的清单和命名规则。
- **代码要点**：文件夹格的文字标签设 `o=2`（文档落入的那一步消失），文档的 keyframe 同时改 `x y w h` 和 `html`（只留标题行），否则 QA 报 TEXT_COLLISION 和 LAYOUT_OVERFLOW。材料来自 CRO 时，用 `Verbatim('src/<材料>.md')` 引用，小字写“项目流程（CRO）”。
- **demo**：docs_pack。

## P16 真实表单模拟
- **用途**：日志卡、入组审核表、CRF 页、知情同意签字页。
- **构图**：一张大的 `doc_mock` (0,0,620,440)，按原表格画行列（只画与讲解相关的 6–10 行）；右侧放规则卡和反例卡。
- **scene**：表单结构 → 正确填写一行（文字逐格出现）→ 漏填（留空并写原因）→ 涂改（划线旁改、签名和日期）→ 回收时核对。
- **代码要点**：表格线用细长的 `p.el`（宽或高为 1）按画布坐标画出来，不要在 `inner` 里写带 px 尺寸的 `<table>`：inner 里的 px 不随幻灯片缩放，宽屏下会和叠加的格子错位。逐格出现用多个 `p.el` 叠在对应格子上，设置不同 `s`；同一格先错后对用 `s=3, o=4` 和 `s=4` 两个元素。
- **demo**：diary_form。

## P17 解剖 / 示意图标注
- **用途**：疾病部位、给药部位、作用机制、器械操作。
- **构图**：示意图占 (0,0,~560,~400)，用 `svgart` 或生图（`mix-blend-mode:multiply`）；引线标注 `p.wire` + `tag`；右侧放 `kv_card` 或步骤卡。
- **scene**：整体图 → 逐层或逐部位标注 → 药物作用或禁区（红色 ×、斜线阴影）→ 给药或操作要点。
- **代码要点**：分层图用 `moa_layers()` 返回的四层，在同一个框里叠放，设置不同 `s`。
- **demo**：bg_drug。

## P18 三色分类 + 落入 chip
- **用途**：合并用药（允许、需讨论、禁止）、AE 分级、资料是否可接受。
- **构图**：三列容器（绿、琥珀、红，各 360×330，标题上方写类别名的原文），上方是待分类的药物 chip 行；底部放旁白。
- **scene**：三类定义（原文）→ chip 逐个落入（`chip(..., k={k: {'x':…, 'y':…}})`）→ 容易放错的 chip 先落错列（`c: 'err'`），下一步移到正确列 → 原文中“需与申办者讨论”的范围。
- **代码要点**：三列容器加 `style='display:block'`；chip 的落点用一个 `slot(列, 行)` 函数计算，避免手写坐标互相压住；chip 文字不超过 10 个汉字。
- **避免**：把方案已明确归类的药物放进“需讨论”。
- **demo**：conmed。

## P19 漏斗 + 案例卡
- **用途**：AE 判定层级（是否 AE → SAE → AESI → 相关性）、筛选失败原因分层。
- **构图**：左侧漏斗 4 层（梯形用 `clip-path`，或者用宽度递减的 `pn`，宽 520→280），每层写判定问题；右侧放案例卡位 `case_card`。
- **scene**：漏斗层级 → 案例 A 逐层下落（token 或高亮层）→ 案例 B 停在第二层 → 异常值判 NCS（必须写理由的反例和正例）。
- **代码要点**：层序号放在左侧，token 沿各层右端下落（`p.path` 连接各层右端点），避免盖住序号和文字；层内左边距写 `calc(58 * var(--kz-u))`，不要写 px。
- **demo**：ae_judge。

## P20 蛇形标准流程
- **用途**：项目很多的访视（V1）、EOT 访视、样本处理流程。
- **构图**：节点按 S 形排 3 行，每行 4–5 个节点（`nd` 170×56），行末用弯曲 `wire` 转到下一行；每个节点上标序号；顺序约束用红色虚线标出“必须在……之前”。
- **scene**：第一行 → 第二行 → 第三行 → 顺序陷阱（两个节点调换，`k` 移位，红线）→ 恢复正确顺序。
- **避免**：节点超过 15 个；需要缩小字号才能放下时，拆成两页。
- **代码要点**：用 `slot(n)` 算第 n 个位置（偶数行从左到右，奇数行从右到左）；序号徽标画在槽位上、不跟节点走，顺序陷阱用两个节点的 keyframe 互换 `x y` 并加 `c: 'bad'`，下一步写回原坐标。行末弯线留在画布内（x 不小于 0、不大于 1168）。
- **demo**：v1_flow。
